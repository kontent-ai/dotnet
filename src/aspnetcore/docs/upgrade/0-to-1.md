# Upgrade Guide: Kontent.Ai.AspNetCore 0.x → 1.0

This guide covers upgrading from `Kontent.Ai.AspNetCore` **0.16.x / 0.17.x** to **1.0**.

Coming from 0.15 or earlier? 0.16 aligned the package with `Kontent.Ai.Delivery` 19, which replaced the
`IImage` interface with `IAsset`; the `img-asset` tag helper's `asset` attribute takes `IAsset` since then
and no view changes are needed for assets returned by the Delivery SDK. Move to 0.16 first, then follow
this guide.

The major exists because the package moves to .NET 10 and onto `Kontent.Ai.Delivery` 20, and because the
public surface was tightened while the package was still pre-1.0. Two changes are behavioural and worth
reading even if the compiler is quiet: a missing webhook secret now fails instead of admitting requests
([§3](#3-a-webhook-secret-is-required)), and webhook payloads that lack a documented member now fail to
bind ([§5](#5-webhook-models-have-required-members)).

## At a glance

| Change | Effort |
|---|---|
| `net8.0` → `net10.0` | Move your project to .NET 10 first; see [§1](#1-target-net-10) |
| `Kontent.Ai.Delivery` 19 → 20 | Follow the Delivery [19 → 20 guide](../../../delivery/docs/upgrade/19-to-20.md); see [§2](#2-delivery-20) |
| `WebhookOptions.Secret` is required | Set it; see [§3](#3-a-webhook-secret-is-required) |
| Every public type is `sealed`; webhook models are `record`s with `init` members | Nothing, unless you derived from one or mutated a payload; see [§4](#4-sealed-types-and-record-payloads) |
| Webhook models have `required`, non-nullable members | Drop null checks; add the members if you construct payloads by hand; see [§5](#5-webhook-models-have-required-members) |
| `WebhookNotification.Notifications` is `IReadOnlyList<WebhookModel>` | `Length` → `Count`, `WebhookModel[]` → `var`; see [§5](#5-webhook-models-have-required-members) |
| `Reference` removed | Delete the usage; nothing produced or consumed it |
| `SignatureMiddleware.WebhookOptions`, `AssetTagHelper.ImageTransformationOptions` no longer public | Nothing; they were dependency-injected values |
| `UseWebhookSignatureValidator(predicate, null)` no longer resolves | Use the two-argument overload for container-resolved options |
| `SignatureMiddleware` is `internal` | `UseMiddleware<SignatureMiddleware>()` → `UseWebhookSignatureValidator(predicate)`; see [§6](#6-signaturemiddleware-is-internal) |

## 1. Target .NET 10

There is no multi-targeting. A project on .NET 8 cannot install 1.0 at all — restore fails with
`NU1202: Package Kontent.Ai.AspNetCore is not compatible with net8.0`.

```xml
<TargetFramework>net10.0</TargetFramework>
```

## 2. Delivery 20

The package depends on `Kontent.Ai.Delivery`, `Kontent.Ai.Delivery.Abstractions` and `Kontent.Ai.Urls`
at **20.0** or later. Registering the Delivery client is one builder now, and caching attaches to it; the
[Delivery 19 → 20 guide](../../../delivery/docs/upgrade/19-to-20.md) maps every form. Nothing in this
package's own API changed for it: the tag helpers take the same `IAsset` and `IRichTextContent`, and
`AddKontentRichText` takes the same `IHtmlResolverBuilder`.

## 3. A webhook secret is required

`SignatureMiddleware` used to hash the request body with an *empty key* when `WebhookOptions.Secret` was
unset, so anything signed with that same empty key passed validation. It now throws
`InvalidOperationException` naming the setting. Set the secret to the value shown in the webhook's
settings in Kontent.ai:

```json
"WebhookOptions": {
  "Secret": "<your_secret>"
}
```

There is no configuration in which the previous behaviour was safe.

## 4. Sealed types and record payloads

Every public type is `sealed`. `WebhookNotification`, `WebhookModel`, `WebhookData`, `WebhookMessage`
and `WebhookItem` are `record`s with `init` members: nothing mutates a payload after it is bound, and two
of them compare by value member by member. Object initializers still compile; assigning a property after
construction does not:

```csharp
var item = new WebhookItem { Codename = "hero", /* … */ };
- item.Codename = "hero_v2";
+ item = item with { Codename = "hero_v2" };
```

## 5. Webhook models have required members

The members the API sends for every event are `required` and non-nullable, as they are on the Sync and
Delivery models: `Notifications`, `Data`, `Message`, `System`, `Id` (now `Guid`, not `Guid?`), `Name`,
`Codename`, `LastModified`, `EnvironmentId`, `ObjectType`, `Action`, `DeliverySlot`. The members that
depend on the kind of object stay nullable: `Collection`, `Workflow`, `WorkflowStep`, `Language`, `Type`,
`TaxonomyGroup`, `ActionContext`.

Reading code loses its null checks:

```csharp
- foreach (var n in notification.Notifications ?? [])
- {
-     var codename = n.Data?.System?.Codename ?? throw new InvalidOperationException();
+ foreach (var n in notification.Notifications)
+ {
+     var codename = n.Data.System.Codename;
```

Code that constructs a payload by hand — a test, a replay tool — must set every required member, or it
does not compile. A payload that lacks one fails to bind with `JsonException` (a 400 from model binding)
instead of arriving with nulls; the documented payloads all carry them.

`Notifications` is `IReadOnlyList<WebhookModel>` rather than `WebhookModel[]`. Indexing, `foreach` and
LINQ are unchanged; `Length` becomes `Count`, and a variable declared as `WebhookModel[]` becomes
`IReadOnlyList<WebhookModel>` or `var`.

## 6. `SignatureMiddleware` is internal

The middleware is registered through `UseWebhookSignatureValidator`, which wraps it in the `UseWhen`
branch it expects. A direct registration becomes:

```csharp
- app.UseWhen(ctx => ctx.Request.Path.StartsWithSegments("/webhooks"), b => b.UseMiddleware<SignatureMiddleware>());
+ app.UseWebhookSignatureValidator(ctx => ctx.Request.Path.StartsWithSegments("/webhooks"));
```

The middleware also reads `WebhookOptions.Secret` once, when the host builds its pipeline. A host without
one fails to start with `InvalidOperationException` naming the setting ([§3](#3-a-webhook-secret-is-required)).

## What did not change

- The tag helpers' element and attribute names, and what they render.
- `AddKontentRichText` and both of its overloads.
- The webhook signature algorithm and the header names. A request with a valid signature under 0.x has a
  valid signature under 1.0.
- The JSON property names on the webhook models.
